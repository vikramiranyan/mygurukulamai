# Gurukulam AI — Production Integration Checklist

## Implemented
- Typed frontend API client for Child CRUD.
- Bearer-token authorization on Child API requests.
- Server-authoritative Child ID contract.
- Teacher mapping normalization and immutable lesson-memory updates.
- API client regression test.

## Required environment wiring
- Frontend: `VITE_API_BASE_URL`
- Backend: `DATABASE_URL`
- Backend: `GOOGLE_CLIENT_ID`
- Backend: `JWT_SECRET`
- Backend: `FRONTEND_ORIGINS`

## Acceptance gate
- [ ] Backend reachable from production frontend
- [ ] Google sign-in returns a valid application session
- [ ] Create child persists after refresh/sign-out/sign-in
- [ ] Modify child persists after refresh
- [ ] Delete child persists after refresh
- [ ] One parent's children cannot be read or modified by another parent
- [ ] Child ID is generated by server and cannot be changed by the client
- [ ] Production build and tests are green
- [ ] Browser desktop/mobile/tablet acceptance passes
